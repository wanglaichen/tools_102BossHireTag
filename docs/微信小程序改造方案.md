# 微信小程序改造方案

> 目标：在保留现有 Flask + Redis 业务的前提下，新增微信小程序客户端。  
> 原则：**后端复用、前端重做、先鉴权再上线**。  
> 状态：P0/P1/P2 已落实。  
> 新手入门（申请账号/联调/提审）：见 `docs/微信小程序从零上手指南.md`  
> 发版部署：见 `docs/小程序发版与部署说明.md`

---

## 1. 改造目标与边界

### 1.1 目标
- 手机端可用：查看公司列表、新增/编辑/删除、筛选搜索、导入导出、配置状态/行业
- 与现有 Web 端共享同一套 Redis 数据
- Web 管理端可继续保留（电脑端录入更方便）

### 1.2 不做 / 延后
- 不把 Redis 连接信息打进小程序包
- 不重写 `company_service.py` / `storage.py` 核心业务
- 桌面专属能力（列拖拽、侧栏缩放、双击编辑）小程序不复刻
- 代理设置（`/api/proxy`）不对普通小程序用户开放

---

## 2. 架构方案

```
微信小程序（miniprogram/）
    │  wx.request / wx.uploadFile / wx.downloadFile
    ▼
HTTPS API（Flask，现有 app.py 扩展）
    │  Token 鉴权
    ▼
company_service + Redis（可复用）
```

| 组件 | 位置 | 说明 |
|------|------|------|
| 小程序 UI | `miniprogram/` | 新建，原生微信小程序 |
| API | `app.py` + `services/` | 保留，补登录鉴权 |
| 数据 | Redis | 继续用现有 key 设计 |
| Web 端 | `templates/` + `static/` | 可选保留，作管理端 |

**推荐方案：保留 Flask API + 新建小程序客户端（不整体重写后端）。**

## 3. 现有能力盘点

### 3.1 可直接复用
- `services/company_service.py`：CRUD、导入解析、CSV、汇总
- `services/storage.py`：Redis / JSON fallback
- API 路径与返回结构：`/api/companies`、`/api/settings`、`/api/summary` 等
- Redis key：`REDIS_KEY_PREFIX` / `REDIS_SETTINGS_KEY` 等

### 3.2 必须改造
| 能力 | Web 现状 | 小程序做法 |
|------|----------|------------|
| 页面 | HTML + Bootstrap | 小程序页面 + 组件 |
| 请求 | 同域 `fetch` | `wx.request` + `baseUrl` |
| 鉴权 | 无 | 微信 `code` 换 session/token |
| 导入 | 粘贴框 + 选文件 | 选聊天文件 / 剪贴板 |
| 导出 | `<a href>` 下载 | `downloadFile` + `openDocument` / 分享 |
| 表格 | 多列宽表 | 卡片列表 + 详情页 |
| 域名 | localhost / Vercel | HTTPS 备案域名 + 合法域名白名单 |

## 6. API 约定（小程序侧）

### 6.1 复用接口（需带 Token）
| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/summary` | 汇总 |
| GET | `/api/companies?time_filter=` | 列表 |
| POST | `/api/companies` | 新增 |
| PATCH | `/api/companies/<id>` | 更新 |
| DELETE | `/api/companies/<id>` | 删除 |
| GET/PATCH | `/api/settings` | 字典 |
| POST | `/api/companies/import` | 导入合并 |
| POST | `/api/companies/import-overwrite` | 导入覆盖 |
| GET | `/api/companies/export.csv` | 导出 CSV |
| GET | `/api/companies/export.json` | 导出 JSON |
| GET | `/api/version` | 版本号 |

### 6.2 新增接口
| 方法 | 路径 | 用途 |
|------|------|------|
| POST | `/api/auth/login` | `{ code }` → `{ token, user }` |
| GET | `/api/auth/me` | 校验当前 Token |

### 6.3 小程序不开放 / 仅管理员
- `POST /api/shutdown`
- `GET|POST /api/proxy`
- `POST /api/companies/fix-history`（可放到高级设置）

### 6.4 鉴权方式（拟定）
1. 小程序 `wx.login` 拿 `code`
2. 服务端用 `WECHAT_APPID` + `WECHAT_SECRET` 换 `openid`
3. 签发短期 Token（Redis 存 session，或签名 JWT）
4. 后续请求 Header：`Authorization: Bearer <token>`

开发期可用「开发 Token」开关，方便无 AppSecret 时联调。

## 7. 环境变量（拟新增）

```env
# 微信小程序
WECHAT_APPID=
WECHAT_SECRET=
# 开发联调：允许固定开发 Token（生产务必关闭）
MINIAPP_DEV_TOKEN=
MINIAPP_AUTH_REQUIRED=1
```

生产必须：
- HTTPS 域名
- 微信公众平台配置 request / download / upload 合法域名
- Vercel 或国内主机配置 `REDIS_URL`、`WECHAT_*`

## 9. 风险与注意

1. **安全**：现 API 无鉴权，上小程序前必须加 Token，否则等于公开可写库  
2. **域名**：不能用裸 IP；localhost 仅开发者工具  
3. **剪贴板**：需用户手势，体验弱于 Web 粘贴  
4. **表格密度**：手机端必须降维成卡片  
5. **跨境延迟**：若 API 仍在 Vercel，国内访问可能慢，后续可迁国内云  
6. **密钥**：`WECHAT_SECRET`、`REDIS_URL` 只放服务端

## 11. 验收标准

- 开发者工具可登录并拉取公司列表
